# 整合需求與安全護欄

示範版只有**模擬實作**（`src/lib/connectors.ts`）。本文件列出接上正式服務前必須滿足的條件。所有供應商能力、配額與費率須在上線前向原廠重新確認。

## 共通原則

- 憑證只放伺服器端（環境變數／祕密管理），**不得**出現在前端、日誌或操作紀錄。
- 所有對外動作：預覽 → 驗證 → 有權限者核准 → 送出 → 記錄回執（`ActionEvent.externalReceipt`）→ 可重送／撤回。
- 對外發送與財務異動需兩人原則（例：會計審查、主管核准，且不可同一人）。
- Webhook 與排程工作必須冪等（事件 ID 去重）、可重試並有 dead-letter。
- 示範環境永遠顯示「模擬／外部發送未啟用」，不得宣稱已整合。

## LINE 官方帳號（Messaging API）

**用途**：月結對帳單通知、客戶 LINE 下單、供應商叫貨訊息。

- 需金吉利擁有的 LINE 官方帳號與 Messaging API channel；推播只能送給**已加入官方帳號且完成帳號綁定**的使用者，不能推給任意 LINE 聯絡人。
- 帳號綁定：以一次性、短效的綁定流程把 `lineUserId` 連到客戶（`Customer.linkStatus`），提供解除綁定。
- **PDF 不以附件傳送**：官方帳號訊息包含一個 HTTPS 安全連結，連到需驗證身分的入口下載 PDF。
  - 連結短效（示範設 7 天）、可撤銷、可重發；物件存放於私有儲存，逐客戶授權；可選浮水印。
  - **禁止**只憑客戶編號或可猜測的 URL 取得帳單；需防列舉。
- 只記錄「送達」狀態，不宣稱「已讀」。
- 供應商 LINE 群組：需機器人在群組內且收到 group ID 事件、成員權限明確；未驗證者改電話叫貨（示範中「綠原蔬食工坊」即為此狀態）。
- 訊息配額與費用依地區方案而定，上線前確認。
- 備援：安全入口 + Email／簡訊或人工分享連結。

介面：`LineStatementSender.preview(customer, statement)` / `send(customer, statement)`。

## 綠界 ECPay 電子發票

**用途**：日結客戶逐筆開立、月結客戶月底彙開；作廢與折讓。

- 前置：綠界商店申請、API 金鑰、沙盒測試、會計師確認稅務處理。
- 需分別追蹤 **綠界接收狀態** 與 **財政部上傳狀態**（`providerStatus` / `govUploadStatus`），兩者不可混為一談。
- B2B：買方統一編號（含檢查碼）；不可使用載具。B2C：手機條碼（`/` + 7 碼）、自然人憑證、會員載具或紙本。
- 品項層級稅別、含稅／未稅單價正規化、捨入規則（示範：每張單據四捨五入至元）。
- 開立日期規則、字軌配號、免稅品項、二聯／三聯用語、折讓與作廢流程皆須會計師確認。
- 每次送出需使用者確認；示範中只有模擬回應，沒有任何實際開立或申報。

介面：`EcpayInvoiceProvider.preview(inv)` / `submit(inv)` / `status(providerRef)`。

## ECOUNT（既有 ERP）

- 先前探訪結論為此客戶**無法使用 ECOUNT API**；在承諾重建 ERP 前須向原廠重新確認。
- PoC 期間 ECOUNT 仍為主帳（system of record）。以 CSV 匯入／匯出分段遷移：預覽 → 驗證 → 對帳 → 寫入；與 ECOUNT 並行一個月結週期，並保留回滾方案。
- 匯入需以 `external_id` 去重；數量、單位、價格欄位逐行驗證（示範：設定 → 試匯入 ECOUNT CSV）。

介面：`ErpSync.exportOrders(orders)` / `importOrders(csv)`。

## 正式上線前的非功能需求

角色權限（RBAC）、傳輸與儲存加密、租戶隔離、財務期間鎖、只增不改的稽核紀錄、伺服器端產生 PDF、自動備份與還原演練、監控與告警、個資保護（LINE ID、付款憑證、會計資料依角色限制）、保存期限政策。

## 尚待金吉利確認

實際場地尺寸與各凍庫品項；貨車載重；客戶座標與收貨時段；送貨單是否簽收；誰收款、如何繳回與核對匯款；稅務例外與發票時點；LINE 官方帳號擁有權與客戶綁定意願；綠界憑證；ECOUNT 資料匯出的法律與技術可行性；供應商同意以 LINE 叫貨。
